# AGENTS.md — RealmForge

Instructions for any coding agent (Codex, Claude Code, Hermes subagents) working in this repo. Read this first, then [docs/SPEC.md](docs/SPEC.md). Track progress in [docs/CHECKLIST.md](docs/CHECKLIST.md): update it whenever you finish or start an item.

## What this is
A university project for the **Blockchain BK-01** module, done by a team of two students. The grade is 100% the project: a working DApp with smart contracts that answers a real business need, plus an oral exam on security, performance and design choices (learning outcomes AA4–AA6).

**RealmForge** is a browser game in the style of **Mario Maker**:
- Players build 2D platformer levels with rich physics.
- They publish each level as an **ERC-721 NFT**.
- Other players play it solo, in co-op or in versus races, paying fees and earning the **ERC-20 FORGE** token.
- Creators earn from plays, and level NFTs can be resold with royalties.

Mockups: `docs/mockups/*.png`. Full spec: `docs/SPEC.md` (PDF version: `docs/RealmForge_Spec.pdf`).

## Locked decisions (do not change without the team agreeing)
| Topic | Decision |
|---|---|
| Platform | **Web only**. No desktop or native build. Unity and Unreal were evaluated and rejected. |
| Engine | **Phaser 3.90 (not Phaser 4)** + **Matter.js** physics, fixed 60 Hz step |
| Movement | **Mario-like** (SMB1 / Mario Maker 2 feel), deterministic fixed-point maths, in `game-core/` |
| On-chain vs off-chain | **No gameplay on-chain.** The chain holds ownership (levels), the economy (FORGE) and settlement. Physics, rooms and validation are off-chain. |
| Trust model | The game server validates runs and signs **EIP-712** results; the contracts verify signer, nonce, deadline, chainId and contract address. The signer is a known centralisation point: document it, never hide it. |
| Contracts | Exactly **2 minimum, one per student, each with a token**: Student A `LevelNFT.sol` (ERC-721 + ERC-2981), Student B `ForgeCoin.sol` (ERC-20 + Permit + Capped + Pausable) |
| Chain | Hardhat local (31337) for development, **Sepolia** for the demo |
| Level storage | Level JSON on IPFS; only `layoutHash = keccak256(canonical JSON)` is stored on-chain |
| Assets | **CC0 only** (Kenney, OpenGameArt CC0). **No Nintendo assets, names or code.** Every source goes in `assets/CREDITS.md`. |
| Code reuse | Prefer existing public code, but only MIT/Apache/BSD/CC0. Repos with GPL or no licence are for reference only; never copy from them. |

## Cross-package contracts (must stay in sync)
- **EIP-712 domains:** `RealmForge LevelNFT` / `RealmForge ForgeCoin`, version `"1"`. The typed messages are:
  - `ClearProof(address creator,bytes32 layoutHash,uint256 deadline)`
  - `RunResult(address player,uint256 levelId,uint32 timeMs,bool cleared,uint16 coins,uint256 nonce,uint256 deadline)`
  - `RaceResult(bytes32 roomId,address[] ranking)`
  - `SeasonResult(uint256 season,address[] players,address[] creators,uint256[] shares)`

  A server test checks these strings against `contracts/src` word for word. If you change one side, change both and run both test suites.
- **ABIs:** generated by `contracts/scripts/export-abi.ts` into `web/src/contracts/generated/` and `server/abi/`. Never hand-edit the generated files; re-export them after any contract change.
- **`ILevelNFT`** is frozen (SPEC §6). Changing it needs both students to agree.
- **Level format** `level.v1.json` (SPEC §3.4) and the canonical-JSON hashing must produce identical `layoutHash` values in web and server. Keep the shared test vector passing.
- **Movement constants** live in `game-core/`; server validation must import them, not copy them.
- **Colyseus:** server 0.16 must match the web client `colyseus.js` 0.16. Upgrade both together.

## Smart contract rules
- Solidity `^0.8.24` (compiled with 0.8.28), OpenZeppelin v5 only, no hand-rolled ERC implementations.
- Payments use the pull pattern + `nonReentrant` + checks-effects-interactions. Use custom errors, emit an event for every state change, enforce roles with `AccessControl`.
- Signature verification must bind nonce, deadline, chainId and verifying contract.
- Leave `TODO(studentA)` / `TODO(studentB)` markers in place: these are the students' design decisions to make and defend. Don't silently resolve them.
- Every new function needs tests for the success path, each revert path and any invariant (use fuzzing where it applies).
- Hardhat 3 notes:
  - `paths.sources = "src"`.
  - tsconfig must include `artifacts/**/*.d.ts`.
  - In Solidity tests, a view call made after `vm.prank` uses up the prank: sign first, then prank.

## Game and web rules
- Before touching Phaser code, load the skill `phaser3-react-matter-pitfalls` if you have it. Known traps:
  - `scene.start` reuses old data, so pass `{resume:true}`.
  - Phaser 3.90 Matter has no `isFixed`; use `runner:{fps:60}` and step the controller once per physics step.
  - Guard against a null Matter world during teardown.
- Gameplay must stay deterministic: fixed 60 Hz, fixed-point maths in game-core, inputs recorded as replay bitmasks.
- Known limit: the elements runtime supports **one player per Matter world**. Multiplayer needs this fixed (see the checklist).
- UI follows the mockups: navy `#0f1424`, violet `#7c5cff`, gold `#ffc83d`. No lorem ipsum.

## Working rules for agents
1. **Stay in your lane.** When several agents run in parallel, each owns specific paths (see `OWNERSHIP.md`). Never edit another agent's paths.
2. **Subagents do not commit.** The coordinator reviews, runs the tests and commits. Never push with failing tests.
3. **Evidence over claims.** Paste real command output (tests, builds) in your report. Never report a passing test you didn't run.
4. **Update `docs/CHECKLIST.md`** (`[ ]` → `[~]` → `[x]`) along with the code change.
5. **No secrets in git.** Only `.env.example`. The only key allowed in examples is the public Hardhat test key, labelled as such.
6. Keep changes focused. Don't restructure packages or upgrade major versions (Phaser, Colyseus, Hardhat, OZ) without being asked.
7. Licence check before adding any dependency or asset; record assets in `assets/CREDITS.md`.

- Cross-package invariants still hold (EIP-712, ABIs, layoutHash, constants).
- `docs/CHECKLIST.md` updated, and the README updated if commands or setup changed.
